What this module shows

Clusters are not always round. DBSCAN (density-based clustering) defines a cluster as a dense region: points with many neighbours close by. It grows clusters from these dense points and follows any shape.

Points in no dense region are labelled noise. For a bank, a card payment at an unusual hour and for an unusual amount is exactly such a point: worth a check for fraud.

How to use it

  1. Start with the card payments: find the noise points.
  2. Change the radius ε and the minimum number of neighbours; click a point to see its ε-neighbourhood.
  3. Try the moons and circles, and compare with k-means below.

Clusters as dense regions

DBSCAN has two settings: a radius ε and a minimum number of points minPts. Around every point draw a circle of radius ε and count the points inside (the point itself included).

  • Core point: at least minPts points in its circle. It lies inside a dense region.
  • Border point: fewer than minPts in its circle, but inside the circle of a core point. It is on the edge of a cluster.
  • Noise point: neither. It belongs to no cluster: an outlier.

The algorithm

  1. Take a core point not yet in a cluster and start a new cluster with it.
  2. Add every point in its ε-circle. For each new core point, add the points in its circle too, and so on, until the cluster stops growing.
  3. Repeat with the next unassigned core point. What is left at the end is noise.

The number of clusters is not chosen in advance: it follows from ε and minPts. A cluster can have any shape, because it grows through chains of dense neighbourhoods.

Choosing ε and minPts

  • minPts: a rule of thumb is about twice the number of inputs (here 4 or 5). Larger values ignore small groups and give more noise.
  • ε: draw the k-distance plot: for every point, the distance to its minPts-th nearest neighbour, sorted. Dense points have small values; the curve bends upward where the noise begins. Choose ε near that knee.
  • Too small ε: many tiny clusters and most points become noise. Too large ε: separate groups merge into one.

Strengths and limits

Finds clusters of any shape and flags outliers. But one ε must fit all clusters, so groups with very different densities are hard; distances must be meaningful, so standardize the inputs; and in many dimensions all distances become similar (see the Curse of Dimensionality module).

Definitions
N_\varepsilon(x) = \{\, y : \lVert x - y \rVert \le \varepsilon \,\}, \qquad x \text{ is a core point} \iff |N_\varepsilon(x)| \ge \text{minPts}

y is directly density-reachable from x if x is a core point and y is in Nε(x). A cluster is a maximal set of points connected through chains of such steps.

Deep dive

Border points that lie in the ε-circles of core points of two clusters are given to the cluster that reaches them first, so their label can depend on the order of the data. Core points and noise do not.

Cost. With a spatial index the neighbour searches take about n log n time in few dimensions; without one, n².

Extensions. OPTICS orders the points by density so all values of ε can be read at once; HDBSCAN builds a hierarchy of density levels and handles clusters of different densities.

References: Ester, Kriegel, Sander and Xu (1996), "A density-based algorithm for discovering clusters in large spatial databases with noise", KDD; Schubert, Sander, Ester, Kriegel and Xu (2017), "DBSCAN revisited", ACM Trans. Database Systems.

From the simulation to real data

  • Fraud and anomaly screening (unusual payments, trades or claims are noise points), geographic clusters (shops, customers, accidents), market regimes in a few indicators.
  • Standardize the inputs, set minPts, read ε from the k-distance plot. In Python: sklearn.cluster.DBSCAN(eps=0.3, min_samples=5); noise points get the label −1.
