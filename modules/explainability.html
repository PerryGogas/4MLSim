What this module shows

A gradient-boosting model can predict house prices well, but it is a sum of hundreds of trees: why does it predict what it predicts? Explainability methods open the black box:

  • Permutation importance: how much worse the predictions get when one input is scrambled.
  • Partial dependence (and ICE curves): how the prediction changes as one input changes.
  • SHAP values: how much each input pushed one particular prediction up or down.

How to use it

  1. Read which inputs matter. Is the street number important?
  2. Choose an input for the partial dependence chart: is the effect straight, curved, the same for every house?
  3. Pick a house and read its SHAP waterfall; compare with the linear regression.

Why explain?

Regulators, managers and clients ask why a loan was refused or a price was set. Explanations also catch errors: a model that relies on an input that should not matter (an ID, a street number, information from the future) is probably wrong. Explainability methods work for any model, because they only look at how the predictions respond to the inputs.

Permutation importance

Shuffle one input's column in the test set (so it no longer matches the other inputs and the price) and measure how much the error grows. A large increase: the model relies on that input. About zero: it does not. Caution: when two inputs are strongly related (size and rooms), the model can use either, so each one alone may look less important than the pair; and shuffling creates unrealistic houses (200 m² with 1 room).

Partial dependence and ICE

Set one input to a value for every house, predict, and average: repeat across the input's range. The curve (partial dependence) shows the average effect: straight, curved, with thresholds. The thin lines (ICE, individual conditional expectation) show the same for single houses: when they are not parallel, the effect depends on other inputs, an interaction (a square metre is worth more near the centre).

SHAP values

For one prediction, SHAP splits the difference between that prediction and the average prediction into a contribution of each input, fairly: each input gets its average marginal contribution over all orders in which inputs could be added (the Shapley value from cooperative game theory). The contributions add up exactly to the prediction minus the average. For a linear regression, the SHAP value of an input is simply coefficient × (value − average value).

Definitions
\text{PI}_j = \text{RMSE}\bigl(f, X^{(j \text{ shuffled})}\bigr) - \text{RMSE}(f, X), \qquad \text{PD}_j(v) = \frac{1}{n} \sum_i f(x_{i,-j}, x_j = v)
\phi_j(x) = \sum_{S \subseteq F \setminus \{j\}} \frac{|S|!\,(p - |S| - 1)!}{p!} \bigl[v(S \cup \{j\}) - v(S)\bigr], \qquad v(S) = \frac{1}{|B|} \sum_{b \in B} f(x_S, b_{-S})
f(x) = v(\varnothing) + \sum_{j=1}^{p} \phi_j(x)

Here the SHAP values are computed exactly over all 25 = 32 coalitions of inputs, with 50 training houses as the background B (interventional SHAP). The additivity, and the linear-model formula, are checked in the module's tests.

Deep dive

Exact versus approximate. With p inputs there are 2p coalitions: fine for 5, impossible for 100. The shap package uses TreeSHAP (exact and fast for trees) and KernelSHAP (sampling) for other models.

Correlated inputs. Interventional SHAP and partial dependence evaluate the model at combinations of inputs that may never occur together. Accumulated local effects (ALE) plots and conditional SHAP variants address this.

Explanations are not causes. They describe the model, not the world. A large SHAP value for an input says the model uses it, not that changing it would change the outcome.
