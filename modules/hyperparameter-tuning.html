What this module shows

Most models have settings that are not learned from the data: the hyperparameters (k in KNN, the depth of a tree, C and γ of an SVM). They are chosen by trying values and scoring each with cross-validation on the training set; the test set is used once, at the end.

Which values to try? Grid search tries every combination of a few values; random search draws the same number of combinations at random. Here both search the C and γ of an RBF support vector machine.

How to use it

  1. Watch the landscape of cross-validation accuracy fill in (in practice nobody sees it).
  2. Press Step: both searches evaluate one combination at a time.
  3. Compare the best settings found, how many different γ values each tried, and the test accuracy.

Parameters and hyperparameters

Parameters are learned from the data when the model is fitted (the coefficients of a regression, the weights of a network, the support vectors of an SVM). Hyperparameters are chosen before fitting and control how the model learns: the price of errors C and the width γ of an RBF SVM, k in KNN, the depth and number of trees, the learning rate.

The procedure

  1. Split the data: training set (80%) and test set (20%).
  2. For each candidate combination of hyperparameters, compute the 4-fold cross-validation score on the training set.
  3. Choose the combination with the best cross-validation score.
  4. Refit the model with it on the whole training set, and evaluate it once on the test set.

Choosing by the test score would make the test score optimistic: the test set would have been used for a decision (see Data Leakage and Data Snooping).

Grid search versus random search

  • Grid search: a few values for each hyperparameter (e.g. C in 0.01, 1, 100, 10000) and every combination. Easy to read, but with g values each, g² combinations try only g different values of each hyperparameter.
  • Random search: draw combinations at random (on a log scale). With the same budget, every combination tries a new value of every hyperparameter. When some hyperparameters matter much more than others (common in practice), random search explores the important ones more finely.
  • Smarter searches (Bayesian optimization, successive halving) use the results so far to choose the next combination.

The landscape

For the RBF SVM, small C or small γ give a too-simple boundary (underfitting); a very large γ, especially with a large C, gives a boundary that wraps around single points (overfitting). The best region lies in between. Here the whole landscape is computed for teaching: 169 combinations × 4 folds = 676 fits. In real work you see only the points your search tried.

What is optimized
(\hat C, \hat\gamma) = \arg\max_{(C, \gamma) \in \mathcal{S}} \; \frac{1}{4} \sum_{k=1}^{4} \text{Accuracy}\bigl(\text{SVM}_{C,\gamma} \text{ fitted on folds} \ne k,\; \text{fold } k\bigr)

𝒮 is the grid or the random sample. Both C and γ are searched on a log scale: log10 C from −2 to 4, log10 γ from −2 to 2. Inputs are standardized within each fit.

Deep dive

Why random search works. If only a few hyperparameters matter, the projection of g² random points on an important axis gives g² distinct values, against g for a grid. The chance that at least one of n random points falls in the best 5% of the space is 1 − 0.95n: 60 points give 95%.

The winner's curse. The best cross-validation score among many combinations is optimistic: some of its advantage is luck in the folds. That is why the final model is judged on the untouched test set, or with nested cross-validation.

References: Bergstra and Bengio (2012), "Random search for hyper-parameter optimization", JMLR; Hsu, Chang and Lin (2003), "A practical guide to support vector classification"; Cawley and Talbot (2010), "On over-fitting in model selection", JMLR.

From the simulation to real data

  • Search on log scales for C, γ, learning rates and penalties; use a coarse search first, then a finer one around the best region.
  • In Python: GridSearchCV and RandomizedSearchCV (with loguniform distributions) in scikit-learn; for time series use TimeSeriesSplit as the cross-validation.
